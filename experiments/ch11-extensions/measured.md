# Измеренное: глава 11

PostgreSQL 16.15 с установленным `contrib`.

## Точка невозврата предъявлена сервером

```
ERROR:  cannot drop extension pg_trgm because other objects depend on it
DETAIL:  index names_trgm depends on operator class gin_trgm_ops
         for access method gin
```

И что именно уедет вместе с расширением:

```
NOTICE:  drop cascades to index names_trgm
```

Это раздел 11.2 словами самого сервера: индекс, построенный классом
операторов из расширения, делает расширение неудаляемым.

## Восстановление без права создать расширение

```
psql:dump.sql:25: ERROR: permission denied to create extension "pg_trgm"
```

Дамп останавливается на строке с расширением.

## Что пришлось починить

Исходный стенд заявлял, что дамп «не восстановится там, где расширения
нет», и восстанавливал его в базу без установленного `pg_trgm`. На
машине с `contrib` он **восстановился**: дамп содержит
`CREATE EXTENSION`, и на сервере, где библиотека есть, эта строка просто
выполняется. Стенд доказывал не то, что заявлял.

Отсутствие библиотеки на машине с установленным contrib не
воспроизвести честно, поэтому стенд переписан на две проверки, которые
воспроизводятся всегда: неудаляемость расширения из-за зависимого
индекса и отказ восстановления у роли без права создать расширение
(сценарий управляемых окружений). В скрипте прямо сказано, какой третий
случай он не воспроизводит и почему.

Попутно: `psql` возвращает ненулевой код на ожидаемой ошибке, из-за
чего скрипт с `set -e` обрывался на середине демонстрации. Ошибка,
которая является частью демонстрации, теперь обрабатывается явно.
