# Стенд, на котором получены все измерения

Все `measured.md` в этом дереве, если в самом файле не сказано иное,
получены на одной установке. Здесь описано то, что общее, чтобы не
повторять в каждом заголовке.

```text
PostgreSQL version:  16.15 (Ubuntu 16.15-0ubuntu0.24.04.1), x86_64
Build commit:        not recorded (пакет дистрибутива, не сборка из исходников)
OS:                  Ubuntu 24.04, контейнер
CPU:                 1 ядро (nproc=1; зафиксировано автоматически только
                     в прогоне ch06, остальные прогоны шли в том же
                     контейнере)
RAM:                 not recorded
Storage:             not recorded (виртуальный диск контейнера)
Filesystem:          not recorded
Dates of runs:       2026-09-06
```

Общие настройки сервера:

```text
shared_buffers = 256MB
max_wal_size   = 4GB      (кроме прогонов главы 1, где менялся намеренно)
fsync          = off      (кроме прогонов главы 1, где включался намеренно)
```

## Что означает `fsync = off` для этих чисел

Он влияет на время и не влияет на объём WAL, число мёртвых строк,
плотность индекса и оценки планировщика. Поэтому:

- величины "сколько байт", "сколько строк", "какая плотность",
  "какая оценка" - пригодны для сравнения между прогонами;
- величины "сколько секунд" - пригодны только для сравнения участков
  **внутри одного прогона** и не переносятся на боевую машину.

Там, где время всё-таки приводится как результат (глава 16, окно
обновления), это оговорено в самом файле.

## Чего у этих измерений нет

Одно ядро и небольшие объёмы означают, что стенд показывает **форму**
явления, а не его величину в production. Ни одно из чисел не является
нормативом. Везде, где число могло бы быть прочитано как норматив, в
файле стоит оговорка.

Повторов больше одного не делалось нигде, кроме случаев, отмеченных
явно. Разброс не измерялся.
