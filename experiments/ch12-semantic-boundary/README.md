# Стенд главы 12: граница семантики

Проверяет утверждение главы: **предварительная проверка в приложении не
является инвариантом базы**.

```sh
createdb sem_bench
export PGDATABASE=sem_bench
./run.sh                      # оба режима
WORKERS=16 ITER=10 ./run.sh   # сильнее конкуренция
```

Нужен `btree_gist` из `contrib`: без него нельзя сочетать равенство по
`resource_id` с пересечением по интервалу в одном ограничении.

Два режима с **одинаковым кодом приложения**:

- `precheck` — `SELECT` «свободно ли», пауза, `INSERT`;
- `constraint` — то же самое, но в базе объявлено
  `EXCLUDE USING gist (resource_id WITH =, tstzrange(...) WITH &&)`.

Смотреть надо не на число вставок, а на столбец «пересечений»: он
считается запросом по таблице и отвечает на вопрос о состоянии мира, а
не о поведении кода.

Пауза между проверкой и вставкой задана явно (50 мс), чтобы окно
открывалось на каждой попытке. В проде оно короче и существует всегда.
