# Эксперимент к главе 11: опись и две проверки

## 1. Опись

```sh
psql -f inventory.sql -d ваша_база
```

Работает на любой базе, ничего не меняет. Показывает установленные
расширения и версии, что загружается при старте, какие фоновые процессы
работают, и три списка "точки невозврата":

- колонки, использующие типы из расширений;
- индексы, построенные классами операторов из расширений;
- индексы на методах доступа из расширений.

Три последних списка - это то, что сломается, если расширения не
станет. Если они пусты, вы на первых уровнях глубины и можете уйти
почти бесплатно. Если нет - расширение является частью вашего формата
данных, и это надо знать до следующего обновления, а не во время.

## 2. Дамп без расширения

```sh
./dump-without-extension.sh
```

Создаёт базу с триграммным индексом, снимает дамп и восстанавливает его
в базу, где `pg_trgm` не установлен. Восстановление останавливается.

Нужен `contrib` (пакет `postgresql-contrib` в большинстве
дистрибутивов). Если `pg_trgm` недоступен, замените в скрипте на любое
другое расширение, дающее тип или класс операторов, - суть не
изменится.

Убрать за собой: `dropdb ext_src; dropdb ext_dst`.

## 3. Сервер, который не стартует

```sh
./wont-start.sh          # сломать и починить
./wont-start.sh clean    # удалить кластер
```

Отдельный кластер в `/tmp/ch11`, вашу установку не трогает. Скрипт
прописывает в `shared_preload_libraries` несуществующую библиотеку,
показывает отказ старта, показывает, что подключиться некуда, и лечит
правкой `postgresql.auto.conf`.

Проделайте это руками хотя бы раз. Три минуты сейчас - против паники в
ту ночь, когда к базе будет не подключиться.

## Что дописать самостоятельно

Стоимость наблюдаемости. Если у вас включён `auto_explain` с
`log_analyze` или другое расширение с накладными расходами на каждый
запрос, измерьте её один раз: `pgbench` при фиксированном темпе с
расширением и без (потребуется перезапуск). Без этого числа разговор об
отключении наблюдаемости будет спором двух мнений.
